Prepaid AI Gateway on Azure API Management

One Azure API Management gateway in front of every team's Azure AI Foundry resource. Teams keep signing in with Entra ID, the platform team gets central monitoring, and each team's spend stops when its prepaid dollar balance runs out.

Summary

Today every team calls its own Foundry resource directly. This design puts a single APIM instance between the teams and their models, and adds a small billing service that keeps a prepaid balance per team in a ledger.

For teams

Only the endpoint changes

Teams keep their Entra ID token for https://cognitiveservices.azure.com and their SDK. They swap the Foundry URL for the gateway URL.

For the platform team

One place to watch and control

Token metrics, logs and throughput limits for every team in one APIM instance and one Log Analytics workspace.

For finance

Prepaid dollars, enforced

Each request is priced from its token usage and deducted from the team's balance. At zero, the gateway returns 402 until the team tops up.

The model calls stay in each team's Foundry resource and subscription, so the Azure invoice is unchanged. The ledger is an internal chargeback and control layer on top.

PoC status

The design was built in the SUB-MSHS-SANDBOX subscription and tested end to end. A gpt-4o call through the gateway was priced and deducted from a prepaid balance, and a call with a zero balance was refused with 402 before reaching the model.

Architecture

Blue boxes and arrows are the request path. Amber boxes are the billing layer you build. Gray arrows run outside the request or after the response is sent.

What happens on one request

  1. The team's app gets an Entra token for https://cognitiveservices.azure.com exactly as it does today, and calls the gateway URL.
  2. APIM validates the token and reads the calling application's ID (appid or azp claim).
  3. APIM looks up the account in its cache. On a miss it calls the billing service, which returns the account, the team's backend and the current balance. Unknown apps get 403.
  4. If the balance is zero or below, APIM returns 402 Payment Required without calling the model.
  5. APIM applies a tokens-per-minute cap per account, emits token metrics, swaps the caller's token for its own managed identity token and forwards to the team's Foundry resource.
  6. After the response, APIM writes a usage event (request ID, account, model, token counts) to Event Hubs. The client does not wait for this.
  7. The billing service reads the event, prices it from the price table and, in one Cosmos transaction, records the charge and deducts the balance. A repeated event with the same request ID is ignored.

Added latency is about 1–2 ms on a cache hit and 15–40 ms on a cache miss, against model calls that take 0.5–30 s.

Every hop authenticates with managed identity: APIM to Foundry, APIM to Event Hubs, APIM to the billing service, and the billing service to Cosmos DB and Event Hubs. The design stores no keys.

Ledger data model

Money is stored as integer micro-USD (1 USD = 1,000,000) so it never drifts from floating-point rounding. Database billing holds three containers.

ContainerPartition keyDocuments
ledger/accountIdOne account document per team (balance, backend, status), plus every charge and topup for that team. Keeping them in one partition is what makes the atomic batch possible.
clients/idMaps an Entra application ID to an account. A team can have several apps.
prices/idRates per model in USD per 1M tokens: input, cached input, output.

Build steps (Azure portal)

Every resource is created by hand in the Azure portal. Sign in as someone who can create resources and assign roles in the target subscription, and who can create app registrations in Entra ID. Portal labels move around between releases, so a menu name may differ slightly from what is written here.

A few settings have no portal screen: the Cosmos DB data role, the APIM-to-Event Hubs logger, assigning an app role to a managed identity, and turning off key auth. For those, open Cloud Shell (the >_ icon in the portal's top bar, Bash mode) and paste the command shown. Nothing needs to be installed on your machine.

Gateway policy

Applied at the API scope. Named values {{tenant-id}}, {{billing-base-url}} and {{billing-app-id-uri}} come from step 8.

Streaming responses can't be parsed without buffering them, which would delay the first token. For streams, the policy charges the total token count at the output rate, which slightly overcharges, and marks the charge estimated. A nightly job corrects estimated charges from the APIM LLM logs.

Billing service code

Python v2 programming model: one Function app with three functions — account lookup for the gateway, the usage-event charger, and the admin top-up.

This is the production version, secured by Entra app roles. The PoC runs a function-key variant instead: AuthLevel.FUNCTION, no role checks, a by field on top-ups, Cosmos DB connected on first use, and balanceUsd, costUsd and amountUsd display fields. In its APIM policy, the billing call sends x-functions-key: {{billing-func-key}} instead of a managed identity token.

App settings: COSMOS_ENDPOINT, and EventHub__fullyQualifiedNamespace set to <namespace>.servicebus.windows.net so the trigger connects with the managed identity. requirements.txt: azure-functions, azure-cosmos, azure-identity.

Risks and open items

ItemImpactMitigation
Overspend windowCharges land a few seconds after the response and balances are cached for 30 s, so a busy team can go slightly negative.Accept a small overdraft, which is recovered from the next top-up. If that is not acceptable, add strict reserve-and-settle for accounts below a threshold.
Streaming accuracyStreamed calls are charged at an estimated rate.Nightly true-up from LLM logs. Confirm in the pilot that tokensConsumed is populated for streamed responses.
Policy and code not yet runBoth follow documented APIM and SDK syntax but have not been executed.Run them in the dev instance with the APIM trace tool and unit tests before the pilot.
Price driftLedger prices fall out of step with Azure prices.Keep the price table in one place and reconcile monthly against Cost Management.
Hot partitionOne very busy team writes to a single logical partition.Serverless handles bursts up to the partition limit. If a team exceeds it, move that team's charge records to a separate container.
Partition sizeA logical partition holds up to 20 GB.Set a TTL on charge documents (for example 400 days) once they are mirrored to reporting.
Single gatewayAn APIM outage stops every team.Standard v2 has an SLA. Premium v2 adds zones and multi-region when the risk justifies the cost.
